# 编译诊断

`@elfui/vite-plugin` 会对宏组件给出构建期诊断。

| 场景                                                       | 处理                                             |
| ---------------------------------------------------------- | ------------------------------------------------ |
| 导入宏 API 但没有导出 `defineHtml()`                       | 补组件导出或删除宏导入                           |
| 使用已移除宏别名                                           | 改为 `defineProps` / `defineEmits` 等新 API      |
| pragma 位置不合法                                          | 移到文件顶部或改用普通 `.ts` 导出                |
| `defineFragment()` 被导出或没有赋值给本地 `const`          | 保持局部声明：`const Card = defineFragment(...)` |
| fragment 模板是动态值或被用作属性值                        | 返回静态模板字面量，并只把 fragment 用作模板内容 |
| fragment 名称与其他局部组件冲突                            | 重命名其中一个局部绑定                           |
| 命名 fragment 形成循环引用                                 | 打破循环；fragment 是编译期切片，不支持递归      |
| `fragment` 的 `array.map()` 内部 key 被误认为列表 identity | 需要稳定重排时改用 `v-for :key`                  |

Vite 启动阶段还会检查 Core、Compiler 与 Vite Plugin 的精确 beta 版本和编译协议。错配会以 `ELF_VITE_VERSION_MISMATCH` 或 `ELF_VITE_PROTOCOL_MISMATCH` 在第一次模板编译前停止，并显示实际解析路径、修复命令和 Vite cache 清理提示。

## 严格模式

```ts
elfuiMacroPlugin({
  strictDiagnostics: true,
  templateTypeCheck: true,
});
```

`strictDiagnostics` 适合 CI；`templateTypeCheck` 适合组件库和 beta 前质量门禁。
